# تسجيل الدخول بـ OIDC

يستطيع داو (Dhow) أن يسمح للناس بالدخول عبر مزوّد هوية خارجي: أي مزوّد OpenID Connect (Google، Keycloak، Microsoft Entra ID، Authentik، ...) وGitHub. يشرح هذا الدليل كيف تسجّل داو لدى المزوّد، وكيف تضبطه، وكيف يربط الناس حساباتهم.

المتغيرات مذكورة في [الإعدادات](../install/configuration.md#مزودو-تسجيل-الدخول). وتصميم الأمان في [نموذج الأمان](../security-model.md#4-المصادقة-adr-0013).

## كيف يعمل

- **المزوّد يُدخل حسابًا موجودًا، ولا ينشئ حسابًا أبدًا.** ما زال الناس ينضمون إلى داو بدعوة ويضبطون كلمة سر. بعد ذلك يفتحون **الحساب** ويربطون مزوّدًا. من تلك اللحظة، زر المزوّد في صفحة الدخول يفتح حسابهم.
- **نطابق الحسابات بالـ subject الذي يرسله المزوّد، وليس بالبريد أبدًا.** الهوية التي بريدها يساوي بريد حساب في داو لا تفتح هذا الحساب حتى يربطها صاحبه. هذا يمنع أي شخص يتحكم في عنوان بريد لدى مزوّد ما من الاستيلاء على حساب.
- **الدخول بخطوتين ما زال يعمل.** الحساب الذي له TOTP أو مفتاح مرور يُطلب منه ذلك بعد المزوّد، تمامًا كما بعد كلمة السر.
- **آخر طريقة دخول تبقى.** يرفض داو فك ربط هوية إذا كان الحساب لن تبقى له أي طريقة دخول.

## 1. اختيار معرف

لكل مزوّد معرّف قصير: حروف إنجليزية صغيرة وأرقام، يبدأ بحرف. يظهر المعرّف في أسماء المتغيرات وفي رابط العودة (redirect URI)، فاختره مرة واحدة واحتفظ به. الهويات المربوطة تتذكر المعرّف الذي رُبطت به، وصفحة الحساب تعرضها به. الأمثلة تستخدم `google` و`corp` و`github`.

## 2. تسجيل داو لدى المزود

سجّل تطبيق ويب (عميلًا سريًا، confidential client) بهذه القيم:

- **رابط العودة (Redirect URI):** `<DHOW_PUBLIC_URL>/oidc/callback/<id>`، مثل `https://dhow.example.com/oidc/callback/google`. يجب أن يطابق تمامًا.
- **نوع المنح (Grant type):** authorization code. يرسل داو دائمًا PKCE (`S256`)، فتستطيع أن تشترطه.
- **الصلاحيات (Scopes):** `openid email profile` لـ OIDC، و`read:user user:email` لـ GitHub. لا يطلب داو أي شيء آخر.

احتفظ بمعرّف العميل (client id) وسر العميل (client secret) للخطوة التالية.

### Google

1. في Google Cloud console، افتح **APIs & Services → Credentials → Create credentials → OAuth client ID**، ونوع التطبيق **Web application**.
2. أضف رابط العودة تحت **Authorized redirect URIs**.
3. المُصدِر (issuer) هو `https://accounts.google.com`.

### Keycloak

1. في الـ realm الخاص بك، أنشئ client مع تفعيل **Client authentication** و**Standard flow**.
2. أضف رابط العودة تحت **Valid redirect URIs**. وتحت **Advanced**، اضبط **Proof Key for Code Exchange Code Challenge Method** على `S256`.
3. السر تحت **Credentials**. المُصدِر هو `https://<keycloak-host>/realms/<realm>`.

### GitHub

يستخدم GitHub بروتوكول OAuth 2.0 بدون OpenID Connect، لذلك له نوع خاص.

1. افتح **Settings → Developer settings → OAuth Apps → New OAuth App** (ولمؤسسة على GitHub، إعدادات تلك المؤسسة).
2. اضبط **Authorization callback URL** على رابط العودة.
3. ولّد سر عميل.

يعرّف داو حساب GitHub برقمه (id)، وليس باسم الدخول (login)، لأن اسم الدخول يمكن تغييره ثم يأخذه شخص آخر.

مع GitHub Enterprise Server، اضبط `DHOW_OIDC_<ID>_ISSUER` على رابط الخادم، مثل `https://github.example.com`. يستدعي داو الـ API الخاص به تحت `/api/v3`.

## 3. ضبط داو

أبسط طريقة هي الواجهة: افتح **إعدادات السيرفر ← مزوّدو الدخول**، واضغط **أضف مزوّد دخول**، واملأ ما حصلت عليه في الخطوة 2. راجع [إعدادات السيرفر](instance-settings.md#مزودو-الدخول). باقي هذه الخطوة للتثبيتات التي تدير الإعدادات في ملفات، مثل Kubernetes أو GitOps. عند ضبط `DHOW_OIDC_PROVIDERS`، تأتي القائمة كلها من البيئة، وتعرضها الواجهة للقراءة فقط.

اذكر المعرّفات في `DHOW_OIDC_PROVIDERS`، ثم أعطِ كل معرّف متغيراته، والمعرّف فيها بحروف كبيرة:

```sh
DHOW_OIDC_PROVIDERS=google,corp,github

DHOW_OIDC_GOOGLE_ISSUER=https://accounts.google.com
DHOW_OIDC_GOOGLE_CLIENT_ID=1234567890-abc.apps.googleusercontent.com
DHOW_OIDC_GOOGLE_CLIENT_SECRET_FILE=/run/secrets/dhow-oidc-google-client-secret
DHOW_OIDC_GOOGLE_ALLOWED_DOMAINS=example.com

DHOW_OIDC_CORP_ISSUER=https://sso.example.com/realms/staff
DHOW_OIDC_CORP_CLIENT_ID=dhow
DHOW_OIDC_CORP_CLIENT_SECRET_FILE=/run/secrets/dhow-oidc-corp-client-secret
DHOW_OIDC_CORP_NAME=Example SSO

DHOW_OIDC_GITHUB_TYPE=github
DHOW_OIDC_GITHUB_CLIENT_ID=Ov23liExample
DHOW_OIDC_GITHUB_CLIENT_SECRET_FILE=/run/secrets/dhow-oidc-github-client-secret
```

- **سر العميل** سر مثل `DHOW_SECRET_KEY`. فضّل `_CLIENT_SECRET_FILE`، أو مع systemd `LoadCredential=dhow-oidc-<id>-client-secret:...`، حتى لا يظهر أبدًا في `ps` أو `docker inspect`. ضبط أكثر من مصدر يوقف السيرفر.
- **نص الزر** يأتي من `DHOW_OIDC_<ID>_NAME`، أو من المعرّف عندما يكون فارغًا (`GitHub` للنوع `github`). يظهر هكذا: "ادخل بـ <name>".
- **النطاقات المسموحة** (`DHOW_OIDC_<ID>_ALLOWED_DOMAINS`) تقبل الهوية فقط إذا ذكر المزوّد بريدًا موثّقًا نطاقه واحد من القائمة بالضبط. `example.com` لا يسمح بـ `team.example.com`، فاذكر الاثنين إذا احتجت إليهما. استخدمها مع المزوّدين الذين يستطيع أي شخص التسجيل فيهم، مثل Google أو GitHub، حتى تمنع الهويات من خارج شركتك.

أعد تشغيل داو. **أي خطأ في أي مزوّد يوقف السيرفر** برسالة تذكر اسم المتغير: معرّف عميل أو سر ناقص، أو سر مؤقت، أو مُصدِر ليس `https://` (و`http://` العادي فقط مع `DHOW_DEV=true`)، أو نوع غير معروف، أو نطاق مكتوب بشكل خاطئ. لا يتصل داو بالمزوّد عند البدء، لذلك المزوّد المتوقف لا يوقف داو. زره فقط يفشل حتى يعود.

## 4. ربط حساب

1. ادخل بكلمة السر.
2. افتح **الحساب ← حسابات الدخول المربوطة**، واضغط **اربط** بجوار المزوّد.
3. أكّد بخطوتك الحالية (كلمة السر، أو كود TOTP، أو مفتاح مرور). يرسلك داو إلى المزوّد ثم يعيدك.

الربط يُخرجك من أجهزتك الأخرى. كل حساب في داو يربط هوية واحدة لكل مزوّد، والهوية تنتمي إلى حساب واحد فقط في داو.

لفك الربط، اضغط **ألغِ الربط** وأكّد بخطوتك الحالية.

## حل المشكلات

| ما تراه | السبب | ماذا تفعل |
|---|---|---|
| السيرفر لا يبدأ ويذكر متغير `DHOW_OIDC_*` | إعدادات هذا المزوّد غير صالحة | أصلح المتغير الذي تذكره الرسالة |
| "خدمة الدخول غير متاحة الآن" | لم يصل داو إلى وثيقة الاكتشاف (discovery) أو عنوان الرموز لدى المزوّد. ينتظر داو 30 ثانية قبل أن يحاول الاكتشاف مرة أخرى | تأكد أن جهاز داو يصل إلى المُصدِر عبر HTTPS، وأن المُصدِر هو بالضبط ما يذكره `/.well-known/openid-configuration`، ومنه أي `/` في الآخر |
| المزوّد يقول إن رابط العودة لا يطابق | الرابط المسجّل لدى المزوّد يختلف عن `<DHOW_PUBLIC_URL>/oidc/callback/<id>` | سجّل الرابط بالضبط، بالبروتوكول واسم الجهاز والمعرّف نفسها |
| "لا يوجد حساب في داو مربوط بهذه الهوية" | لم يربط أحد هذه الهوية بحساب في داو | ادخل بكلمة السر واربطها من **الحساب** |
| "نطاق البريد في هذه الهوية غير مسموح به هنا" | الهوية ليس لها بريد موثّق في `ALLOWED_DOMAINS` | استخدم حسابًا في نطاق مسموح، أو غيّر القائمة |
| "استغرق الدخول وقتًا طويلًا، أو بدأ من متصفح آخر" | انتهت المحاولة (10 دقائق)، أو اكتملت بالفعل، أو بدأت في متصفح آخر | ابدأ مرة أخرى من صفحة الدخول في المتصفح نفسه |
| "لم ينجح الدخول بهذه الخدمة" | رفض المزوّد الكود، أو فشل رده في فحص (التوقيع، أو المُصدِر، أو الجمهور، أو الانتهاء، أو الـ nonce)، أو الحساب موقوف | راجع سجل السيرفر وسجل المزوّد، ثم حاول مرة أخرى |
| "هذه الهوية مربوطة بحساب بالفعل" | ربطها شخص آخر بالفعل | ألغِ الربط هناك أولًا |
| "حسابك مربوط بهذه الخدمة بالفعل" | كل حساب يربط هوية واحدة لكل مزوّد | ألغِ ربط الهوية الحالية أولًا |

محاولات الدخول الفاشلة عبر المزوّد بعد محاولة صالحة تُسجَّل في سجل الأحداث كـ `auth.oidc_login_failed`، مع السبب.
