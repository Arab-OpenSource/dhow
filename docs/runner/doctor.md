# فحص جهاز التشغيل بالأمر doctor

يفحص `dhow-runner doctor` جهاز تشغيل جهّزه `dhow-runner install`، ويخبرك بما يجب إصلاحه. يحتاج إلى root، ولا يغيّر شيئًا إلا إذا طلبت، ولا يطبع أبدًا رمز التسجيل ولا المفاتيح ولا الهوية.

```sh
sudo dhow-runner doctor
sudo dhow-runner doctor --fix
```

في الطرفية يعرض كل إصلاح مقترح ويسألك عنه. والخيار `--fix` يطبّقها كلها دون سؤال، و`--lang ar` أو `--lang en` يختار اللغة.

## ما الذي يفحصه

| الفحص | يفشل عندما | ما الذي يصلحه |
|---|---|---|
| تثبيت جهاز التشغيل | لا يوجد الملف التنفيذي، أو الخدمة، أو `runner.env`، أو مجلد الحالة، أو المستخدم `dhow-runner`. | `sudo dhow-runner install` |
| Podman 5.4 أو أحدث، وcrun وnewuidmap | Podman غير موجود أو أقدم من 5.4، أو لا يوجد `crun` أو `newuidmap` أو `newgidmap`. لا نفحصه مع مشغّل الاختبار. | Podman أحدث من التوزيعة. |
| cgroup v2 ومساحات أسماء المستخدمين | الـ kernel يستخدم cgroup v1، أو user namespaces معطلة، أو يمنعها AppArmor. | إعدادات الـ kernel التي تذكرها الرسالة. |
| الـ sub-ids | لمستخدم جهاز التشغيل أقل من 65536 sub-id لكل تشغيل في `/etc/subuid` أو `/etc/subgid`. | `--fix` يضيف نطاقًا فارغًا من 1048576. |
| ذاكرة كل تشغيل | مجموع `DHOW_RUNNER_MAX_MEMORY` وقرص tmpfs بحجم `DHOW_RUNNER_MAX_DISK` أكبر من ذاكرة الجهاز. وهو الفحص نفسه الذي يجريه `install` قبل الخطوة الأولى ([الذاكرة لكل تشغيل](install.md#الذاكرة-لكل-تشغيل)). | اخفض القيمتين في `runner.env`، والرسالة تقترح قيمًا مناسبة. |
| وحدة systemd تطابق هذا الإصدار | الخدمة المثبّتة تختلف عن التي داخل الملف التنفيذي (تحذير). | `--fix` يكتبها مرة أخرى ويعيد تشغيل جهاز التشغيل. |
| الخدمة مفعّلة وتعمل | الخدمة متوقفة أو معطّلة. | `--fix` يفعّلها ويعيد تشغيلها. |
| تقوية الوحدة | يقيّم `systemd-analyze security` الخدمة بأكثر من 6.9. | أعد الخدمة الأصلية واحذف ملفات drop-in التي تخفف قيودها. |
| ملكية الملفات وصلاحياتها | لملف أو مجلد مالك أو صلاحية غير التي يعطيها `install`، أو ملف حالة هو رابط رمزي أو ملف خاص. | `--fix` يعيد المالك والصلاحية عبر واصف ملف (descriptor) لا يتبع الروابط أبدًا. ولا نصلح الرابط الرمزي أو الملف الخاص أبدًا: احذفه بنفسك، واعتبر مفاتيح جهاز التشغيل مكشوفة. |
| حفظ الهوية | الهوية مشفّرة لكن ملف الـ drop-in الخاص بها غير موجود، أو توجد نسخة غير مشفّرة ونسخة مشفّرة معًا، أو لا توجد هوية. والهوية غير المشفّرة بالصلاحية `0600` نعرضها كمعلومة مع السبب. | `--fix` يكتب ملف الـ drop-in مرة أخرى. |
| لا يوجد تغيير مفاتيح لم يكتمل | بقي `identity.pending` أو `identity.pending.cred` من تدوير (تحذير). | أوقف جهاز التشغيل وشغّل `sudo dhow-runner rotate-keys`. |
| السيرفر يرد | لا يمكن الوصول إلى السيرفر، أو شهادته غير موثوقة. | العنوان، أو DNS، أو الجدار الناري، أو `DHOW_RUNNER_CA_FILE`. |
| جهاز التشغيل يسجّل الدخول | يرفض السيرفر جهاز التشغيل، أو لم تسجّل الخدمة الدخول منذ بدأت. | الرسالة وسجل الخدمة يذكران السبب. |

مجلد الحالة قد تكون صلاحيته `0700` أو `0711`. مشغّل Podman يجعلها `0711` عند كل بدء (ADR-0056)، حتى يمر user namespace الخاص بالتشغيل عبر المجلد ويصل إلى نقاط الربط وقناة التحكم الخاصة به. يستطيع الآخرون الدخول إليه، لكن لا يستطيعون عرض محتواه أو قراءته. يقبل `doctor` الصلاحيتين، ولا يعيد `--fix` الصلاحية `0711` إلى `0700` أبدًا، وكل ما بداخله يبقى بصلاحياته الصارمة. ويجب أن يبقى المالك `dhow-runner`، دون أي صلاحية قراءة أو كتابة للمجموعة أو للآخرين.

## كيف يفحص تسجيل الدخول

لجهاز التشغيل جلسة واحدة في كل وقت. إذا سجّل `doctor` الدخول بجانب الخدمة العاملة، فسيستبدل جلسة الخدمة، وثلاثة استبدالات في عشر دقائق توقف جهاز التشغيل مؤقتًا على أنه نسخة مشكوك فيها ([نسخ جهاز تشغيل](register.md#نسخ-جهاز-تشغيل)). لذلك ما دامت الخدمة تعمل، يطلب `doctor` من السيرفر تحدي تسجيل دخول فقط، وهذا يثبت أن السيرفر يرد دون أن يفتح جلسة، ثم يقرأ تسجيل الدخول من سجل الخدمة منذ آخر بدء لها. وعندما تكون الخدمة متوقفة، يسجّل `doctor` الدخول بنفسه.

## المخرجات ورمز الخروج

```
  ok    Runner installed
  ok    Podman 5.4.0 or newer, crun and newuidmap
        Podman 5.4.2
  ok    Unit hardening (systemd-analyze security at most 6.9)
        5.2 MEDIUM
  ok    Identity storage
        The identity is encrypted with systemd-creds in /var/lib/dhow-runner/identity.cred; only this host can open it. (yes, with the host key)
  ok    The runner signs in
        Runner 0190c8a2-… signed in when the service started (from its log, so the running service keeps its session).

Everything looks good.
```

يخرج `doctor` بالرمز 0 عندما يكون كل شيء سليمًا، وبالرمز 1 عندما يبقى تحذير أو فشل، حتى تستطيع السكربتات وأدوات المراقبة استدعاءه.
