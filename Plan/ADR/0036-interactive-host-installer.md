# ADR-0036: الـ installer التفاعلي على السيرفر (`dhow-server install`)

- **الحالة:** مقبول
- **التاريخ:** 2026-10-27
- **بيكمّل:** [ADR-0024](0024-install-methods.md) (مسار الـ binary وsystemd). الرقم 0035 محجوز لـ ADR تنفيذ نواة الهوية في PR #10.

## السياق
- `docs/install.md` بيشرح Docker Compose بس، والمستخدم لازم يجهّز Postgres والـ reverse proxy والـ TLS بإيده.
- المطلوب installer يجهّز السيرفر كله لوحده، وبيستشير المستخدم في كل حاجة: user مخصص للخدمة، والاعتماديات الناقصة (بيسأل قبل ما ينصّب أي حاجة). ولو Docker موجود بيسأل يستخدمه ولا لأ.
- المستخدم بيحدد حدود التنصيب بنفسه: ممكن ياخد داو بس على Postgres وproxy موجودين عنده.
- `docs/roadmap.md` كان حاطط binary وsystemd وHelm في M10.

## القرار
- **الشكل:**
  - bootstrap صغير بـ bash (`deploy/install/get.sh`، حوالي 50 سطر). بيعرف المعمارية، وبينزّل الـ binary من الـ release، وبيتحقق من `SHA256SUMS` وتوقيع cosign، وبعدها بيشغّل `dhow-server install`.
  - الـ installer نفسه في Go، كـ subcommand في `dhow-server`، يعني artifact واحد. كل أوامر النظام بتتبني كـ argv من غير shell.
- **التوزيعات:** Debian وUbuntu وRHEL وRocky وAlma وFedora، وكل واحدة ليها اختبار في الـ CI. أي توزيعة تانية بتاخد «وضع يدوي»: الـ installer بيقول إيه الناقص، ويكمّل الباقي من غير ما ينصّب packages.
- **المكوّنات (كل واحد اختياري، والمستخدم بيختار):**
  - user نظام `dhow` من غير shell ولا home.
  - PostgreSQL 18 من مستودع PGDG، أو قاعدة موجودة (URL وفحص اتصال).
  - reverse proxy: Caddy بـ TLS تلقائي، أو nginx، أو proxy موجود (والـ installer بيطبع الإعداد المطلوب)، أو مفيش.
  - خدمة systemd متقفّلة، والأسرار بـ `LoadCredential=`.
  - الـ firewall: يفتح 80 و443 بس، ولو اتطلب.
- **Docker:**
  - لو موجود، الـ installer بيعرض المسارين:
    - من غير Docker (الافتراضي والأكثر أمانًا).
    - Docker Compose، ومعاه تحذير صريح إن جروب `docker` بيدي صلاحيات root.
  - الـ installer مابيضيفش أي user لجروب `docker` من نفسه.
- **الأوضاع:**
  - **تفاعلي:** خطوة خطوة، وفي الآخر الخطة كلها بتتعرض قبل أي تغيير.
  - **`--answers file.yaml`:** للتكرار أوتوماتيك.
  - **`--dry-run`:** بيطبع الخطة بس.
  - **`doctor`:** بيفحص التنصيب، ويعرض الإصلاح، ومابيطبّقوش غير بموافقة أو `--fix`.
  - **`uninstall`:** بيسيب البيانات إلا لو اتطلب مسحها صراحة.
- **إعادة التشغيل:** تشغيل الـ installer تاني على نفس السيرفر بيكمّل الناقص ومابيبوّظش الموجود.
- **الأسرار:** بتتولّد على السيرفر، وبتتكتب بصلاحية `0600`، ومابتظهرش في الـ output ولا الـ logs ولا ملف الإجابات.
- **الترتيب:**
  - الـ binary وsystemd والـ installer بيتقدّموا من M10 لدلوقتي.
  - Helm بيتأجل لـ M3 عشان يتعمل مرة واحدة والـ runners جواه.

## البدائل اللي اتدرست
- **installer بـ bash بس:** مألوف وسهل يتقري، لكن installer فيه خيارات كتير على توزيعات مختلفة بيبقى هش وصعب يتختبر، وبيبني أوامر shell من مدخلات المستخدم.
- **Docker Compose كافتراضي لو Docker موجود:** أسهل، لكنه بيخلّي المسار الأقل أمانًا هو الافتراضي.
- **Ansible role:** مناسب للفرق الكبيرة، ومش مناسب لمستخدم عنده VPS واحد. ممكن يتعمل بعدين فوق ملف الإجابات.

## العواقب
- الـ release فيه binaries لـ `linux/amd64` و`linux/arm64`، وكل واحد معاه checksum وتوقيع وSBOM.
- `Config` بيقرا `DHOW_SECRET_KEY_FILE` و`DHOW_DATABASE_URL_FILE`.
- **الـ CI:** job لكل توزيعة بيشغّل الـ installer بملف إجابات في container فيه systemd، وبيتحقق من `/health/ready` وتسجيل الدخول، وبعدها `doctor` و`uninstall`.
- حجم `dhow-server` بيزيد شوية بسبب كود الـ installer، وكود الـ installer عمره ما بيشتغل في وضع السيرفر.
